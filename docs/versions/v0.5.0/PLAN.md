# خطة إصدار سيل v0.5.0 (SAYL v0.5.0 Release Plan)

## 1. النطاق (Scope)

يركز هذا الإصدار على بناء منظومة الإضافات الخارجية الآمنة والمعزولة بالكامل باستخدام بيئة تشغيل WebAssembly (WASM) داخل حزمة `crates/plugin-host`. يشمل النطاق توفير وسيط أذونات صارم يمنع وصول الإضافات المباشر لنظام الملفات أو الشبكة دون تصريح صريح، وتطبيق حدود الوقود (Fuel) والذاكرة والوقت، وتطوير حزمة أدوات تطوير الإضافات (Plugin SDK)، وتوفير خطافات محددة النطاق (Scoped Hooks) لمعالجة الروابط واستخراج البيانات وعرض عناصر واجهة تصريحية (Declarative UI Tiles)، بالإضافة إلى بناء كتالوج الإضافات والثيمات المعتمدة (Plugin & Theme Catalog) داخل التطبيق وعلى الموقع الرسمي.

---

## 2. المهام بأرقامها (Tasks)

| رقم المهمة (Task ID) | الوصف بسطر واحد (One-Line Description) |
|---|---|
| **`PLUG-001`** | بناء بيئة تشغيل WASM المعزولة (Wasmtime) وتطبيق وسيط الأذونات وحدود الوقود والذاكرة والمهلات الزمنية. |
| **`PLUG-002`** | تطوير حزمة أدوات تطوير الإضافات (Plugin SDK) وبناء إضافة خارجية مرجعية تثبت استخلاص الروابط والتحقق. |
| **`PLUG-003`** | توفير خطافات محددة النطاق لمعالجة ترويسات الطلبات، والعمليات اللاحقة، وبطاقات الواجهة التصريحية. |
| **`CATALOG-001`** | بناء كتالوج الإضافات والثيمات داخل التطبيق والموقع الرسمي لدعم التثبيت والتحديث والتحقق من التوقيعات. |

## 3. شروط القبول (Acceptance Criteria)

- **عزل أمني صارم (Sandboxing):** تشغيل وحدات WASM في بيئة معزولة تماماً بدون وصول افتراضي لنظام الملفات، أو الشبكة، أو متغيرات البيئة، أو استدعاء أوامر النظام (No Shell Execution).
- **وسيط أذونات صريح (Permission Broker):** أي طلب اتصال شبكي أو قراءة إعدادات يجب أن يمر عبر وسيط المضيف (Host Broker) الذي يتحقق من مطابقة النطاق للقائمة البيضاء المصرح بها (`network allowlist`) وموافقة المستخدم الصريحة.
- **حدود الموارد ومقاومة الانهيار:** احتساب استهلاك الوقود (Fuel Metering) بدقة وتعيين سقف أقصى للذاكرة والوقت؛ وإذا تعطلت وحدة WASM أو استنفدت وقودها تطلق مصيدة (Trap) دون التسبب بانهيار التطبيق المضيف (Fault Isolation).
- **واجهات تصريحية نقية (Declarative UI):** تقتصر واجهات الإضافات على توليد هياكل بيانات تصريحية (JSON/Data Schemas) لعرض بطاقات معلوماتية، ويُحظر حقن أو تشغيل كود JavaScript أو HTML حر داخل واجهة سطح المكتب.
- **توقيع وفحص الكتالوج:** التحقق من صحة توقيعات حزم الإضافات وبصمات التجزئة في الكتالوج الرسمي لمنع توزيع إضافات خبيثة أو معدلة.
- **دورة حياة متكاملة للإضافات:** تمكين المستخدم من استعراض، وتثبيت، وتعطيل، وإلغاء تثبيت أي إضافة بضغطة زر مع حذف كافة مخلفاتها التخزينية.

## 4. الاختبارات المطلوبة (Required Tests)

1. **اختبارات خرق العزل الأمني (Sandbox Escape Tests):** محاولات برمجية متعمدة للوصول لنظام الملفات والشبكة من داخل وحدة WASM والتحقق من اعتراضها ورفضها الحتمي من قِبل وسيط المضيف.
2. **اختبارات استنفاد الموارد والحصص (Fuel & Memory Exhaustion Tests):** تنفيذ حلقات تكرار لا نهائية واستهلاك مكثف للذاكرة داخل الإضافة والتحقق من التقاط الـ Trap وإنهاء المهمة بأمان دون التأثير على استقرار التطبيق.
3. **اختبارات حزمة SDK والإضافة المرجعية (Plugin SDK Integration Tests):** بناء واختبار إضافة مرجعية تستخرج روابط تحميل وتتحقق من توافقها مع واجهات برمجة المضيف.
4. **اختبارات دورة حياة الإضافات (Lifecycle Management Tests):** اختبار التثبيت والتحديث والتعطيل والإزالة والتأكد من تنظيف كافة المسارات والأذونات.
5. **اختبارات فحص توقيعات الكتالوج (Catalog Signature Verification Tests):** محاكاة حزمة إضافة معدلة أو غير موقعة والتحقق من رفض تحميلها أو عرضها في الكتالوج.

---

## 5. ما يعتمد عليه من الإصدار السابق (Dependency on Previous Release)

يعتمد هذا الإصدار على:
- استقرار البنية الهندسية لنواة التطبيق ومحرك التنزيل في `v0.1.0`.
- نظام إدارة الوسائط والبروتوكولات المكتمل في `v0.2.0` و`v0.4.0` لربط خطافات الإضافات معها.
- نظام المظاهر والثيمات في واجهة المستخدم لإتاحة تثبيت الثيمات من الكتالوج.
- توثيق معايير الأمان وسياسة الخصوصية الصارمة للمشروع.
