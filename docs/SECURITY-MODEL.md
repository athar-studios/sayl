# نموذج الأمان والخصوصية (Security & Privacy Model)

تحدد هذه الوثيقة النموذج الأمني، وحدود الثقة، ومصفوفة التهديدات والمعالجات، وسياسة الخصوصية الصارمة، والفجوات المعروفة لتطبيق **سيل (SAYL)**.

---

## 1. حدود الثقة (Trust Boundaries)

يعتمد تصميم النظام على عزل واضح لطبقات ومكونات التطبيق:

1. **الشبكة الخارجية غير الموثوقة (Untrusted Network):**  
   تشمل خوادم الويب، ومحتويات استجابات HTTP، والروابط المدخلة، ورؤوس الترويسات (`Headers`)، وأسماء الملفات المقترحة. تُعامل جميع البيانات الواردة من الشبكة على أنها مدخلات عدائية محتملة تتطلب فحصاً وتطهيراً صارماً.
2. **حدود التواصل بين الواجهة والنواة (IPC Boundary):**  
   تفصل بين واجهة الويب (Svelte داخل Tauri Webview) وبين المحرك المكتوب بلغة Rust. لا تملك واجهة المستخدم وصولاً مباشراً لنظام الملفات أو تنفيذ أوامر النظام، بل تتواصل حصراً عبر أوامر Tauri المحددة والمفحوصة المعاملات.
3. **نظام الملفات ونظام التشغيل المحلي (OS & Filesystem Boundary):**  
   تشمل مجلد التنزيل ومجلد بيانات التطبيق `%APPDATA%\SAYL`. يتم تقييد عمليات الكتابة بملفات وسيطة `.part` ومطابقة المسارات لمنع الكتابة خارج النطاق المخصص.
4. **بيئة تشغيل الإضافات المعزولة (Future Plugin Boundary):**  
   حدود عزل برمجية مستقبلية تفصل بين كود الإضافات المكتوب بواسطة أطراف ثالثة ونواة التطبيق عبر وقت تشغيل WebAssembly (WASM).

## 2. مصفوفة التهديدات والمعالجات (Threats & Mitigations)

| التهديد الأمني | طبيعة المخاطر | المعالجة الدفاعية في سيل (Mitigation) |
|---|---|---|
| **إعادة التوجيه الخبيثة (Malicious Redirect)** | إعادة التوجيه لبروتوكولات محلية مثل `file:///`، أو عناوين السحابة الحساسة (`169.254.169.254`)، أو حلقات لا نهائية، أو تسريب بيانات الاعتماد. | - حظر صارم لكافة المخططات خارج `http` و `https`.<br>- سقف أقصى لا يتجاوز 5 قفزات (`DEFAULT_MAX_REDIRECT_HOPS`).<br>- كشف الحلقات اللانهائية بتسجيل الروابط المزارة.<br>- تجريد رؤوس `Authorization` و `Cookie` و `Proxy-Authorization` فور تغير النطاق (Host / Port / Scheme). |
| **حقن الترويسات (Header Injection / CRLF)** | حقن فواصل أسطر `\r\n` للتلاعب بالاستجابات أو تزوير طلبات HTTP غير مصرح بها. | - رفض وتطهير أي قيم تحتوي على فواصل أسطر `\r` أو `\n` في المعاملات.<br>- استخدام مكتبة `reqwest`/`hyper` التي تطبق فحصاً صارماً لمحارف الترويسات وتمنع تجزئة الطلبات (HTTP Request Splitting). |
| **اجتياز المسارات وأسماء ويندوز المحجوزة (Path Traversal & Reserved Names)** | استغلال اسم الملف في `Content-Disposition` لكتابة ملفات في مسارات النظام الحساسة (مثل `../../System32`) أو استخدام أسماء أجهزة Windows المحجوزة (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`). | - دالة `sanitize_filename` تزيل فوراً أي مسارات نسبية أو فواصل (`..`, `/`, `\`).<br>- استبدال المحارف المحجوزة في Windows (`<>:"/\|?*`) والمحارف غير المرئية بالرمز `_`.<br>- تحييد أسماء الأجهزة المحجوزة بإضافة بادئة آمنة مع الحفاظ على الامتداد (مثل: تحويل `CON.txt` إلى `_CON.txt`).<br>- تطبيق معيار Unicode NFC وضبط سقف الطول الأقصى عند 255 حرفاً. |
| **الأجسام المقتطعة أو المتضخمة (Truncated or Oversized Bodies)** | انقطاع الاتصال مبكراً واعتماد ملف ناقص كأنه مكتمل (False Complete)، أو إرسال تدفق غير منتهٍ لإغراق القرص. | - التحقق الإلزامي من تطابق البايتات المكتوبة بدقة مع رأس `Content-Length` قبل إعلان الاكتمال.<br>- إرجاع `StreamOutcome::Incomplete` عند انقطاع الاتصال بدلاً من إنهاء الملف.<br>- الكتابة المجزأة عبر مخازن محددة (64 KiB) مع التحقق من سعة التخزين. |
| **تخفيض التشفير (TLS Downgrade)** | محاولات هجوم رجل المنتصف لإعادة توجيه اتصال آمن `https` إلى اتصال غير مشفر `http`. | - رفض التحويل التلقائي من `https` إلى `http` عند طلب مسار آمن.<br>- تفعيل التحقق الإلزامي من شهادات TLS وسلاسل الثقة عبر مستودع شهادات النظام (Native TLS). |
| **إعادة ربط DNS واستهداف العناوين الخاصة (DNS Rebinding & LAN Scanning)** | استغلال أسماء نطاقات تشير إلى شبكات داخلية (`127.0.0.1`, `10.0.0.0/8`, `192.168.0.0/16`) لاختراق أجهزة الشبكة المنزلية. | - فحص وتصفية عناوين IP بعد التحليل لمنع توجيه الطلبات لعناوين الاسترجاع (Loopback) أو العناوين المحلية (Link-Local) في مسارات الاستكشاف الآلي والإضافات.<br>- حظر وصول الإضافات للشبكة المحلية دون إذن صريح من المستخدم. |
| **هجمات Zip-Slip في الأرشيفات المستقبلية** | احتواء ملفات الأرشيف (ZIP/TAR) على مسارات نسبية هاربة تخرج عن مجلد فك الضغط. | - تطبيق التحقق المعياري الصارم للمسارات عند فك الأرشيف في الميزات المستقبلية.<br>- مطابقة المسار الناتج والتأكد من أنه يبدأ حصراً بالمسار المطلق لمجلد الوجهة (Canonical Path Prefix Verification) ورفض أي مسار شاذ. |
| **نطاق عزل الإضافات (Plugin Sandbox Scope)** | محاولة كود إضافات خارجي تنفيذ أوامر في سطر الأوامر أو قراءة ملفات خاصة. | - بيئة تشغيل WASM فقط؛ لا وصول مباشر لنظام الملفات أو الشبكة أو متغيرات البيئة افتراضياً.<br>- نموذج أذونات تفصيلي (Declarative Permissions) مع قائمة بيضاء للنطاقات المصرح بها.<br>- وضع حدود لاستهلاك الذاكرة والوقود ووقت التنفيذ لمنع تجميد التطبيق. |

## 3. الخصوصية وما يجمعه التطبيق (Privacy & Zero-Telemetry Commitment)

الالتزام الصريح والنهائي لمشروع سيل:
> **«لا نرسل سجل تنزيلاتك أو روابطك أو ملفاتك إلى أي خادم خارجي. لا يحتوي التطبيق على تحليلات استخدام (No Analytics)، ولا إعلانات، ولا تتبع، ولا رفع لتقارير الأعطال. كافة بيانات التنزيل تُعالج وتُخزن محلياً على جهازك حصراً.»**

- **انعدام التتبع (Zero Telemetry):** لا يوجد أي معرف جهاز فريد (No Hardware/Device ID)، ولا جمع لإحصائيات الاستخدام، ولا تسجيل للجلسات.
- **انعدام الاعتماديات الخارجية الخفية:** لا يتم تحميل خطوط الويب من خوادم Google، ولا أدوات مساعدة خارجية، ولا إطارات تتبع داخل الواجهة.
- **الحدود التقنية الصادقة:** لكي يقوم البرنامج بتنزيل ملف ما، يجب عليه بطبيعة الحال الاتصال بالخادم المضيف للملف. هذا الخادم سيرى عنوان IP الخاص بك وسجل الطلب كما يراه أي متصفح ويب. نحن لا نخفي عنوان IP الخاص بك عن خادم الملف مالم تستخدم وسيطاً (Proxy) أو شبكة خاصة (VPN).

## 4. التعامل مع البيانات الحساسة والأسرار (Secret Handling)

1. **حجب الأسرار في السجلات التشخيصية (Log Redaction):**  
   يتم حجب وتشفير أي رموز مصادقة (`Bearer Tokens`) أو كلمات مرور أو مفاتيح سرية في معلمات الرابط (`query parameters`) قبل طباعتها في السجلات المحلية أو ملفات التتبع.
2. **عزل بيانات الاعتماد عبر النطاقات:**  
   لا يتم نقل ملفات تعريف الارتباط (`Cookies`) أو رؤوس التفويض عند الانتقال لنطاق خادم آخر خلال عمليات إعادة التوجيه.
3. **أمان الإعدادات المحلية:**  
   تُخزن إعدادات البرنامج في ملف `settings.json` محلي، ولا يُطلب من المستخدم أو يُخزن أي كلمات سر غير لازمة.

## 5. الفجوات والحدود الأمنية المعروفة حالياً (Explicit Known Gaps)

نوضح هنا بكل شفافية الفجوات الحالية قيد التطوير:

1. **غياب شهادة التوقيع الرقمي حتى الآن (No Code Signing Yet):**  
   الملفات التنفيذية لنسخ المطورين الحالية غير موقعة بشهادة EV معتمدة، مما يسبب ظهور تحذيرات Windows SmartScreen عند أول تشغيل.
2. **إثبات هوية نماذج الوكلاء بيئي (Model Identity Attestation is Env-Var Based):**  
   في مسار التحقق وضمان جودة الوكلاء (`agent harness`)، يعتمد تمييز النماذج والأدوار على متغيرات البيئة المحلية وليس على إثباتات هوية مشفرة بالعتاد (Hardware/TPM Attestation).
3. **بيئة عزل الإضافات قيد التخطيط ولم تُنفذ بعد (No Plugin Sandbox Implemented Yet):**  
   حزمة `sayl-plugin-host` وبيئة تشغيل WASM هي مواصفات معمارية لم تدخل حيز التنفيذ بعد؛ وبالتالي لا يدعم التطبيق حالياً تشغيل أي إضافات برمجية خارجية، ولن يتم تفعيلها إلا بعد بناء واختبار بيئة العزل الصارمة.
